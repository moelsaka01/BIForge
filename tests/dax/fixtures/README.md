# DAX harness fixture

Synthetic data generated by `node tools/dax-fixtures/generate.mjs` (deterministic; rerunning it rewrites identical files). Six tables:

| File | Rows | Purpose |
| --- | --- | --- |
| Date.csv | 731 | Contiguous calendar 2023-01-01 .. 2024-12-31 (time intelligence) |
| Customer.csv | 10 | One customer (10) never buys; one blank BirthDate; one blank Segment |
| Product.csv | 9 | One product (9) never sold; one blank Color |
| Promotion.csv | 4 | Related to Sales in BOTH directions; promotion 4 never used |
| Sales.csv | 241 | Fact table. Edge rows: SalesKey 17 has CustomerKey 99 (not in Customer); 33 has a blank ProductKey; 50 and 51 have no ShipDate; 77 is a return (Quantity -2); 90 has a blank Quantity; 241 ships on 2025-01-03 (outside Date) |
| Budget.csv | 6 | Year x Category budget, deliberately unrelated (for TREATAS) |

Note: Power BI loads an empty text field of a CSV as an empty string (not BLANK); the engine test fixture (crates/engine/tests/fixture) does the same so the recorded results line up.

## Build the fixture report in Power BI Desktop

1. Start Power BI Desktop and open a **Blank report**.
2. **File > Options and settings > Options > CURRENT FILE > Data Load**: uncheck **Auto date/time**. Click OK.
3. **Home > Get data > Text/CSV**, pick `tests\dax\fixtures\Date.csv`, click **Load** (not Transform). Repeat for `Customer.csv`, `Product.csv`, `Promotion.csv`, `Sales.csv`, `Budget.csv`. Keep the detected types (dates as Date, keys and Quantity as Whole number, prices and Discount as Decimal number, IsWeekend as True/False).
4. **Modeling > Manage relationships**: delete anything that is not in this list, then create the missing ones (**New relationship**) so exactly these five exist:

   | From (many side) | To (one side) | Cardinality | Cross-filter direction | Active |
   | --- | --- | --- | --- | --- |
   | Sales[OrderDate] | Date[Date] | Many to one | Single | Yes |
   | Sales[ShipDate] | Date[Date] | Many to one | Single | **No** (uncheck "Make this relationship active") |
   | Sales[CustomerKey] | Customer[CustomerKey] | Many to one | Single | Yes |
   | Sales[ProductKey] | Product[ProductKey] | Many to one | Single | Yes |
   | Sales[PromotionKey] | Promotion[PromotionKey] | Many to one | **Both** | Yes |

   Budget has no relationships.
5. In the **Data** pane select the **Date** table, then **Table tools > Mark as date table**, choose the **Date** column, OK.
6. Add no measures, columns or visuals (cases are run as DAX queries against this model).
7. **File > Save as > Browse this device**, set **Save as type** to **Power BI project files (\*.pbip)**, and save as `C:\dev\BIForge\research\_raw\dax-fixture\DaxFixture.pbip` (create the folder). That folder is gitignored: Desktop writes its own theme and report files there, which must never be committed.
8. Close Desktop. When the recorder is ready I will ask you to reopen this file so its local engine can answer the recorded queries.
